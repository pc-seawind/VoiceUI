# XVF3800 Integration Notes

## First Checks

List capture devices:

```powershell
python -m voiceui --list-audio-devices
```

Record the command stream:

```powershell
python -m voiceui --config config.example.yaml --record-wav recordings\command.wav --seconds 5
```

Record the wake stream:

```powershell
python -m voiceui --config config.example.yaml --record-wav recordings\wake.wav --audio-purpose wake --seconds 5
```

Calibrate the first energy VAD threshold in a normal quiet room:

```powershell
python -m voiceui --config config.example.yaml --calibrate-vad --seconds 10
```

Use the returned `recommended_vad_threshold` as the first value for
`vad.threshold`, then test with real commands and TV/music noise.

On Linux, also check ALSA:

```bash
arecord -l
arecord -D plughw:4,0 -c 2 -r 16000 -f S16_LE -d 5 output.wav
```

Replace `4` with the actual card number.

## Audio Streams

Keep two logical streams in the design:

- Wake stream: beamformer or ASR-oriented output for wake word and VAD.
- Command stream: AEC/post-processed output for STT.

The right choice depends on measured accuracy. During bring-up, record the same
commands from both streams and compare wake reliability and STT word error rate.

If the device exposes interleaved multi-channel PCM, set `audio.channels` to the
reported channel count and use `audio.wake_stream_channel` plus
`audio.command_stream_channel` to select the logical mono stream for each stage.
For example, use `channels: 2` when ALSA recording works with `-c 2`, and use
`channels: 6` when the device list reports a 6-channel capture endpoint.

## ASR Output

The XVF3800 can expose an ASR-oriented beamformer output. It is useful for wake
word engines because it avoids some non-linear post-processing that can hurt ASR.
Enable and route it with the vendor `xvf_host` utility according to the current
firmware documentation.

Example from the vendor flow:

```bash
sudo xvf_host AUDIO_MGR_OP_R 7 3
sudo xvf_host AEC_ASROUTONOFF 1
```

Tune `AEC_ASROUTGAIN` only after recording real wake-word samples at the target
device position.

## Speaker Output

Prefer a speaker path that the XVF3800 can account for in echo cancellation.
Avoid Bluetooth speakers for the first prototype because their latency makes
barge-in and echo cancellation harder.

## Bring-Up Checklist

- Device name is stable after reboot.
- Capture sample rate is fixed at 16 kHz for wake/STT.
- Playback volume is high enough but not clipping.
- Wake word works while the room is quiet.
- Wake word works while the assistant is playing audio.
- VAD does not stay open on fan, TV, or music noise.
